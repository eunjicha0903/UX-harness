# Harness Goal (R2)

- 상태: CONFIRMED (사용자 승인 2026-10-25)
- 공통 하네스 문서. 프로젝트 값은 `projects/<slug>/`에서 읽는다.

## 1. 해결할 문제

PRD·업무 자료와 화면(Figma)을 대조해 다음을 찾아낸다. 최종 결정은 디자이너가 한다(story-work §6).

| ID | 문제 |
|---|---|
| P1 | 요구사항·정책 누락 |
| P2 | 사용자 흐름·예외 상황 UX 문제 |
| P3 | 컴포넌트 목적·상태·동작 문제 |
| P4 | 화면 간 기능·데이터·상태 불일치 |
| P5 | 수정으로 인한 다른 화면 추가 수정 |
| P6 | 플랫폼 간 영향 (예: 앱↔관리자웹) |
| P7 | 근거 부족·미해결 항목 |

## 2. 사용자와 시점

| 항목 | 값 |
|---|---|
| 실행자·수신자 | 디자이너 1인. 모든 결과를 직접 보고 수정할 때 참고한다 |
| 게이트 위치 | story-work §2의 게이트(멈칫) 열 W1~W14에서 도출한다. 배치는 R3(pipeline)·R5(gates)에서 확정 |
| 조건부 단계 | 디자인 가이드 검토(W14)는 프로젝트에 `design.md`가 있을 때만 활성화 |

## 3. 실행 모드

단일 모드: **전체 검증**. 매 실행마다 story-service 검증 범위의 모든 화면을 대상으로 하고, 화면 간 영향 분석(관련 화면·플랫폼 간 영향 포함)을 항상 수행한다.

## 4. 프로젝트마다 달라지는 입력 (`projects/<slug>/`)

- `story-service.md`: 서비스 맥락·필수 규칙·플랫폼 허용 목록·검증 범위
- `sources/`: PRD·Notion·Figma 스냅샷
- 화면·컴포넌트 목록 / 영향 맵 / 검증 결과·수정 이력
- `story-work-exceptions.md` (있을 때만)

## 5. 판정 체계

### 5-1. 항목 판정 (검증 항목마다 1개)

`PASS` / `FAIL` / `NEEDS_REVIEW` / `INSUFFICIENT_INFO` — 각 판정에 근거와 후속 조치를 기록한다.
자료가 부족하다는 이유로 `PASS`를 주지 않는다.

사용자에게 보이는 곳(Notion·report)에서는 한국어로 표시한다 (사용자 지시 2026-10-28):

| 내부 값 | 판정 | 판정 유형 |
|---|---|---|
| `PASS` | 승인 | — |
| `FAIL` | 검토 필요 | 문제 확인 |
| `NEEDS_REVIEW` | 검토 필요 | 사람 판단 필요 |
| `INSUFFICIENT_INFO` | 검토 필요 | 자료 부족 |

### 5-2. 실행 결과 상태 (실행마다 1개)

| 상태 | 조건 |
|---|---|
| **승인** | 실행 완결성 조건(5-3)을 모두 만족하고, 미해소 항목(FAIL·NEEDS_REVIEW·INSUFFICIENT_INFO)이 0개 |
| **검토 필요** | 실행 완결성 조건을 모두 만족하고, 미해소 항목이 1개 이상. 미해소 항목마다 상세 사유(무엇이·왜·근거·영향 화면·후속 조치)를 남긴다 |
| (실행 실패) | 실행 완결성 조건을 하나라도 어김 → 상태를 부여하지 않고 해당 단계로 되돌아간다 |

해소 조건:

- `FAIL` → 수정 후 재검증에서 `PASS`가 되어야 해소된다.
- `NEEDS_REVIEW` → 디자이너가 검토 사항 보드에서 `수정 완료`를 체크하면 해소된다 (보드 = to do, 수정 완료 = 할 일 완료, 사용자 지시 2026-10-28). `결정 메모`는 선택이다. 체크 이후 근거 자료가 바뀌면 해소를 취소하고 다시 판정한다.
- `INSUFFICIENT_INFO` → 자료를 보완한 뒤 재검증해야 해소된다.
- 필수 규칙(story-service) 판정 조건의 `FAIL`은 컨펌으로 해소할 수 없다. 재검증 `PASS`만 인정한다.

### 5-3. 실행 완결성 조건 (스크립트로 판정)

| ID | 조건 |
|---|---|
| DONE-01 | 필수 산출물 파일이 모두 존재한다 (목록은 R4 `artifacts.md`) |
| DONE-02 | 모든 검증 항목에 판정값이 있다. 빈 값 0개 |
| DONE-03 | 모든 판정에 근거(source_id + 위치: 섹션 또는 Figma 노드 ID)와 후속 조치가 있다. PASS도 근거 필수 |
| DONE-04 | FETCHED가 아닌 근거로 PASS를 준 항목이 0개다 |
| DONE-05 | EXCLUDED 자료를 인용한 항목이 0개다 |
| DONE-06 | 검증 대상 플랫폼이 모두 story-service 허용 목록 안에 있다 |
| DONE-07 | 필수 규칙의 판정 조건이 모두 판정됐다 |
| DONE-08 | 영향 분석: 분석 단위마다 7개 항목(변경 대상·관련 화면·영향 관계 및 근거·예상 문제·수정 필요 여부·판정·후속 작업)이 채워져 있다 |
| DONE-09 | 영향 맵상 연결 화면이 모두 수정 필요 / 수정 불필요 / 추가 확인 필요 중 하나로 판정됐다 |
| DONE-10 | 상태가 "검토 필요"이면 미해소 항목마다 상세 사유 5개 필드가 모두 채워져 있다 |
