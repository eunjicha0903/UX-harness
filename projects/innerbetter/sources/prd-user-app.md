이너베러 사용자 앱 PRD
저칼로리 식단 상품 주문 및 무인 배달 플랫폼
이너베러는 저칼로리·건강식단 상품을 탐색하고 주문하면 정해진 배송 시간에 상품을 받아볼 수 있는 무인 배달 플랫폼입니다.
배경
저칼로리 식단을 관리하는 사용자는 식사나 간식을 선택할 때 칼로리와 영양성분을 함께 고려해야 합니다.
하지만 매번 원하는 상품을 찾고, 상품 정보를 확인하고, 주문 가능한 상품을 비교하는 과정은 번거로울 수 있습니다.
이너베러는 이러한 사용자가 건강식단 상품을 빠르게 탐색하고 주문할 수 있도록 상품 탐색부터 배송 확인까지 하나의 흐름으로 제공합니다.
현재 서비스는 단일 지점을 기반으로 운영하며, 사용자의 핵심 행동은 다음과 같습니다.
상품 탐색
↓
상품 선택
↓
장바구니
↓
주문·결제
↓
배송 확인
초기에는 빠른 주문 경험을 중심으로 제공하되, 향후 여러 지점으로 확장할 수 있는 구조를 고려합니다.
제품 비전
저칼로리 식단 관리를 위한 간편한 상품 주문·배송 플랫폼
이너베러는 사용자가 건강식단 상품을 어렵게 찾고 비교하는 시간을 줄이고,
상품 탐색 → 주문 → 배송 확인
까지 빠르게 이어갈 수 있는 경험을 제공합니다.
제품이 해결해야 하는 핵심 문제
원하는 상품을 빠르게 찾을 수 있어야 합니다.
구매 전에 상품과 영양 정보를 충분히 확인할 수 있어야 합니다.
주문 과정에서 현재 상태와 필요한 정보를 명확하게 확인할 수 있어야 합니다.
무인 배달 특성상 직접 배송 상황을 확인하기 어려운 문제를 보완해야 합니다.
향후 지점이 늘어나더라도 기존 구조를 크게 변경하지 않고 확장할 수 있어야 합니다. 3. 핵심 유저스토리
3-1. 상품을 찾는 사용자
저칼로리 식단을 관리하는 사용자로서, 원하는 건강식품을 카테고리별로 빠르게 찾고 상품 정보를 확인하고 싶다.

3-2. 상품을 주문하는 사용자
상품을 여러 개 선택한 사용자로서, 주문 가능 금액과 최종 결제 금액을 확인하고 빠르게 주문하고 싶다.

3-3. 배송을 기다리는 사용자

취소 가능 여부 확인 4. 사용자들의 상황
사용자는 저칼로리 식단을 관리하며 칼로리와 영양성분을 고려합니다.
원하는 상품을 찾기 위해 여러 상품을 탐색할 수 있습니다.
구매 전 상품의 가격과 영양 정보를 확인할 필요가 있습니다.
여러 상품을 함께 구매할 경우 장바구니에서 총 금액을 확인합니다.
최소 주문 금액을 충족하지 못하면 주문할 수 없습니다.
적립금은 결제 과정에서 자동으로 할인 적용됩니다.
배송 마감 시간과 주문 취소 가능 시간은 정해진 정책에 따라 운영됩니다.
주문 취소는 배송 준비중 상태에서만 가능합니다.
무인 배달 특성상 사용자가 배송 과정을 직접 확인하기 어렵기 때문에 주문 상태를 명확하게 보여줄 필요가 있습니다. 5. 핵심 정보 구조

현재 실제 사용자 데이터가 충분하지 않은 단계라면 수치를 임의로 설정하지 않습니다.
대신 각 Phase에서 검증해야 할 행동을 정의합니다.
Phase 1
주문 경험 검증
상품 탐색 → 상품 상세 이동
상품 상세 → 장바구니
장바구니 → 주문
주문 → 주문 완료
주문 완료 → 배송 상태 이해
정량 데이터가 없다면 프로토타입 사용성 테스트를 통해 확인합니다.
예:
“원하는 상품을 찾아 주문해 주세요.”
이후 사용자가 어느 단계에서 멈추거나 혼란을 겪는지 관찰합니다.
Phase 2
다중 지점 확장성 검증
사용자가 지점을 이해하는가
지점과 상품의 관계를 이해하는가
지점 변경 시 주문 정보가 명확한가
지점별 배송 정책을 이해하는가
Phase 3

이너베러의 초기 설계에서는 다음 조건을 유지합니다.
초기 서비스는 단일 지점 기반
핵심 목적은 건강식단 상품 주문
상품 정보와 영양 정보는 구매 전에 제공
최소 주문 금액 존재
적립금은 자동 적용
배송 마감 정책은 고정
주문 취소는 배송 준비중에서만 가능
배송 상태는 준비중 → 배송 중 → 완료
무인 배달 특성상 배송 상태의 명확한 피드백 필요
향후 다중 지점 확장을 고려

상품, 주문, 배송 정보가 사용자가 필요한 시점에 제공되는가?
정책 일관성
최소 주문 금액, 취소 정책, 배송 정책 등이 화면마다 일관되게 표현되는가?
배송 경험
무인 배달이라는 특성을 고려해 사용자가 자신의 주문 상태를 충분히 이해할 수 있는가?
확장성
단일 지점에서 다중 지점으로 확장할 때 기존 구조를 크게 변경하지 않아도 되는가?
운영 가능성
추천·프로모션·상품 관리 등의 기능이 운영자에게 과도한 관리 부담을 만들지 않는가?
